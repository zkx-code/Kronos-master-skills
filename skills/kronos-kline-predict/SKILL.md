# Kronos K 线预测

中文输出，复用包内 `assets/kronos/model` 的原始 Kronos 核心。脚本路径相对于本技能目录，先解析为绝对路径；输出写到用户任务目录。本包无需原项目仍保留在 E 盘，权重首次运行时从 Hugging Face 下载，行情在本地推理。

## 操作系统与路径

在完整分发包中首次调用时，先读 [包内环境准备](references/package-environment.md)。由Agent检查并按实际任务准备依赖；用户无需双击任何启动器，已有环境不重复安装。

在 macOS 或迁移到其他电脑时，先读 [平台说明](references/platforms.md)。按当前系统解析 Python、工作目录和模型路径；文档中的 Windows 命令仅为示例。

## 周期选择

港股请求先读 [港股接口](references/hk-market.md)。查询某日实际日线、成交额或换手率时，使用 `scripts/hk_daily_quote.py`：Yahoo 日线搭配东方财富成交额、换手率及价格交叉核验，展示实际行情，不启动预测。港股日线或分钟预测继续使用 `scripts/hk_market.py` 获取 Yahoo 行情及 XHKG 交易时段，再调用通用预测器；保持纯价格模式，区分连续交易和收盘竞价。

美股日线、分钟行情或预测请求，先读 [美股接口](references/us-market.md)，使用 `scripts/us_market.py` 获取 Yahoo 行情并准备纽约交易时间，再调用通用 `scripts/predict.py`。美股不进入下面的沪深/北交所盘中入口；Yahoo 无真实成交额，准备与预测均显式使用 `--price-only`。

用户问“几点涨跌、盘中、分时”或指定 1/5/15/30/60/120 分钟时，先读取 [盘中预测](references/intraday.md)，使用 `scripts/intraday.py` 获取/准备分钟行情、生成交易时段和解读结果；未指定分钟周期默认 5 分钟。这个分支覆盖下面的日线默认参数。沪深 A 股全天分别为 240/48/16/8/4/2 根；其他市场需核验各自交易时段，不能套用 A 股调度器。只问某天的日线则沿用日线；目标日休市时如实说明，不擅自替换日期。1/60/120分钟是本 skill 的接口扩展，不表述成原项目已证明这些周期的预测效果。

## 输入与运行

北交所标的先读 [北交所数据与代码](references/data.md#北交所股票)：核验当前上市代码及历史代码变更。盘中准备使用 `scripts/intraday.py prepare --market bse`，接受六位代码或 `bj` 前缀；日线使用核验后的日线 CSV 和交易日序列，调用通用 `scripts/predict.py`，该脚本不需要 `--market`。北交所与沪深常规会话的各周期根数相同，XSHG 仅作共用会话代理，按北交所公告核对目标日休市和标的停牌。

1. 从请求、上下文及现有文件确定标的和市场；用证券名称/完整代码到权威名录核验身份，不擅自选择另一个标的。默认日线、未来 20 根、`small`、400 根上下文、种子 42，说明默认值，已有用户参数优先。标的仍有歧义时只询问标的/市场这一必要信息。
2. **用户没有给 CSV 或数据源时，主动寻找、获取并核验权威行情**，而不是先要求用户准备文件。读取 [行情与交易时间](references/data.md) 的来源优先级和核验流程，使用匹配市场的成熟接口，获取最近已收盘数据及有效交易日历。记录标的身份、周期、复权方式、成交量单位、交易所时区、历史截止和抓取时间。获取失败须定位真实原因，不把来源不明、过期或模拟的数据当最新行情。
3. 准备单一标的、周期和复权口径的 CSV。必须有 `timestamps,open,high,low,close,volume,amount`；使用 `--time-column` 指定其他时间列。纯 OHLC 数据需显式 `--price-only`，这会启用上游支持的零成交量模式并写入元数据。时间必须为交易所当地时间、无时区后缀、严格递增且唯一；零值/缺失/无穷价格、非法 OHLC 直接报错。保留原数据，格式转换另存文件。
4. 预测股票/期货等交易时段市场时，传 `--future-csv`：该文件只需时间列，恰有预测根数，来自交易日历及正确的午休/夜盘/节假日规则。对明确的 24×7 连续市场可用 `--continuous-freq 1h` 等固定间隔。历史验证用 `--holdout`，将最后 N 根价格隔离为真值，脚本只把此前数据输入模型。
5. 读取 [环境与运行示例](references/usage.md)，先执行同参数的 `--check-only`。检查通过才加载模型推理。依赖缺失时在独立 Python 环境安装包内 requirements；根据已有设备选择 PyTorch 版本。下载、设备、数据或推理失败均保留原错误，修正后重试；不生成行情替身、不更换预测算法、不自动切换请求的设备。
6. 正式运行省略 `--check-only`，给一个尚不存在的 `--output-dir`。检查 `forecast.csv` 和 `run.json`，验证模式另有 `actual.csv`。只有脚本成功并核实文件才报告完成。完成格式/输入检查不等于完成模型推理。

## 解读结果

每次预测完成并向用户交付结果时，在当前对话的最终回复末尾独立一段，原样输出以下提示（日线、盘中及历史留出预测均适用；后续单独提取或展示已有预测结果时也附上）：

> 本次是依据清华大学开源的模型预测，不是确定的买卖，不要全盘相信，要有自己的判断。

提示必须直接出现在对话回复中，不能仅写入报告、CSV、工具日志或文件链接；若预测未成功，则如实报告未完成，不使用这句话暗示已有预测结果。

- 报告历史截止点、预测区间、模型、样本数、种子、实际设备、数据来源/复权/单位；给出最后预测收盘价相对最后真实收盘价的变化，并链接生成文件。
- `sample_count` 是多条采样路径的平均，返回值不是单条路径集合，其最高/最低价也不是置信区间。单次随机输出不支持“准确率”“上涨概率”或收益保证。
- 检查 `run.json` 的 `forecast_quality`；异常 OHLC 或负成交量保留原始输出并明确指出，不自动裁剪成看似合理的 K 线。上游自己的标准化和 clip=5 是模型流程，区别于人为涨跌停修正。
- `--holdout` 给出 close MAE、RMSE 和“保持最后收盘价”的基线误差，只代表这一段历史留出效果。多窗口研究按时间滚动切分，调参段与最终测试段分开。预测误差不等于交易策略收益。
- **每次完成预测，默认直接在当前对话展示结果图**，不等用户另行要图。复用 matplotlib、mplfinance 或 Plotly，将图保存到本次输出目录，检查可读性后用 `![预测结果图](绝对路径.png)` 内嵌在最终回复；附数据截止点、预测区间、简短解读及 CSV/报告链接。不能只给图片文件链接或要求用户打开网页查看。
- **每次交付预测结果时，同时生成一份与实际任务匹配的中文 Markdown 报告**，保存在本次输出目录并在最终回复提供可点击链接。日线任务生成“日线预测报告”，分钟线任务生成“盘中走势预测报告”，结合当天已发生行情的任务生成“盘中更新报告”，历史留出或实际行情对比生成“预测验证/实际对比报告”。由当前任务选择合适的名称和内容，不再让用户选报告类型；已有同次报告可完善，避免重复生成。用户明确要求其他语言、格式或不要报告时遵从其要求。
- 报告以本次数据和计算结果为依据，包含：标的与周期、数据截止点和预测范围、来源及复权/单位、模型和采样参数、结果图、关键预测数值与走势解读、OHLC等质量检查、局限、原始数据与运行记录链接。篇幅按任务调整，不为填模板添加无依据的新闻、原因、概率或交易建议。
- 日线报告重点解释收盘变化和预测价格范围；盘中报告列出实际交易时段、预测开高低收及相邻收盘方向，区分根内涨跌与休市跳空；盘中更新报告明确区分已发生行情、预测起点和剩余预测，不改写盘前版本。实际对比/历史验证报告仅在已有对应真值时计算误差、方向命中及可适用的基线比较，并说明样本范围；未来预测报告不虚构准确率或回测结果。
- **逐根预测表格直接写进当前对话最终回复**，使用可读的 Markdown 表格，不仅放在图片、报告或CSV中。至少列出日期/时段、预测开盘、最高、最低、收盘和OHLC异常标记；盘中任务附相邻收盘涨跌方向并说明比较基准。完整量额模式可附量额及单位；纯价格模式不把辅助量额输出当有效预测展示。已有实际行情的对比任务清楚标注实际值、原预测值与误差，保留各次预测起点。
- 展示用户请求范围的完整逐根表格；较长的一分钟或跨日结果按日期、上午/下午拆成连续表格，不静默省略中间行或用下载链接代替。格式化数值可适当四舍五入，保持CSV原始精度，异常用明确文字或带注释的星号标记。
- 报告末尾使用本节指定的模型预测提示；当前对话回复末尾仍按原要求单独显示该提示。完成前核对对话表格、报告、CSV、图表和运行参数一致，实际行情不标成预测，异常预测不隐藏。默认最终交付为：**内嵌结果图＋逐根预测表格＋简短解读＋报告链接＋数据链接**。
- 图中明确区分历史/已发生行情与预测，标记预测起点、价格单位和交易时段；午休期间不画成连续交易。OHLC异常保留标记，改用收盘曲线展示并说明异常，不裁剪原值或画成正常蜡烛。结果与实际对比时直接展示对比图。图表默认随对话语言，无需询问“中文界面还是英文界面”。
- 普通预测和看结果图不启动 WebUI；仅用户明确要求网页交互界面时使用 kronos-webui。读取已有预测结果作图时复用原数值，不重新采样改变预测；用户明确要求只给文字/表格时遵从该要求。
