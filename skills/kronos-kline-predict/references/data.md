# 行情与交易时间

## 数据口径

优先读取用户已有行情。原始数据保留，规范化文件另存。映射由数据源真实字段决定，常见 AKShare 日线映射：`日期→timestamps，开盘→open，最高→high，最低→low，收盘→close，成交量→volume，成交额→amount`。时间列也可能为 `date` 或 `datetime`，可直接使用脚本 `--time-column`。

OHLC 必须数值、有限且大于零，high 至少覆盖 open/close/low，low 至多为 open/close/high；volume/amount 有限且非负。缺字段、重复/倒序时间、空表直接定位问题。文件较短时显式降低 lookback 并报告，不悄悄缩短上下文。不要插值填充停牌价格或用未来数据修复缺值。

volume 与 amount 使用数据源原始且一致的单位，记录手/股/张/币、元/港元/美元等；不要根据字段名擅自换算。AKShare 的不同接口单位可能不同。复权价格与成交额的口径需要说明，不用 `close*volume` 伪造成交额。只拿到 OHLC 时可使用显式 `--price-only`，报告成交量相关输出不作真实成交量预测。

一个 CSV 仅含一种标的及周期，多个标的分开运行。Unix 秒/毫秒时间先按数据源单位解析并转换交易所时区。脚本要求无时区后缀的当地墙钟时间：对于已带时区的 pandas Series，先 `.dt.tz_convert(exchange_timezone)` 再 `.dt.tz_localize(None)`；对于 UTC 的无时区数据，先 `.dt.tz_localize('UTC')` 再转换。避免直接去时区而改变时间含义。

## 获取行情

### 未提供文件或来源时的主动取数

不要把准备历史 CSV 设成用户的必做前置步骤。先从对话、当前文件及任务确定标的；名称可到交易所证券名录核对完整代码。用户未给周期/长度时用日线/20 根并报告；标的本身未知或存在多种身份时仅询问这一点，不随意拿示例股票代替。用户给了文件也要检查覆盖区间和来源；若请求“最新预测”而文件过期，主动补取可核验的新数据，统一口径另存。

按照数据的实际出处选择，工具名称不代表权威性：

1. 对应交易所或官方市场机构公开的行情、证券名录和交易日历。加密资产使用明确指定交易所的官方 K 线接口；不同交易所的同名交易对不混用。
2. 用户已有访问权限的持牌/专业行情服务，核实其交易所来源、延迟、周期与复权规则。
3. 可追溯到明确行情提供方的成熟金融数据服务，例如 AKShare 的具体数据源。记录底层提供方和原始页面/接口地址，不能把聚合库本身称为交易所官方。

优先用已安装且覆盖该市场的成熟客户端，不重写行情协议。需要查找接口时访问官方说明，检查当前版本支持的字段、历史范围和频率。A 股可选 AKShare 的 `stock_zh_a_hist`；指数/港股/期货必须选各自接口。核对代码与市场：`000001` 可能是深市股票，也可能指上证指数，不能只按数字判定。币类可使用 CCXT 的目标交易所 OHLCV 接口，注意通常只有 OHLCV、没有 amount，优先用该交易所真实成交额字段补齐；否则明确报告并选择纯价格模式，不计算伪成交额。

搜索结果摘要、新闻里的价格、走势图目测值及 AI 生成行情不作为模型输入。凭证从现有受支持环境读取，不写入 CSV、命令日志或报告。遇到需要新账号/付费权限的接口时说明所缺条件；已公开可取的数据直接获取。

### 北交所股票

北交所归属必须通过北京证券交易所证券名录（https://www.bse.cn/）和标的全称核验。市场适配器接受 `43xxxx`、`83xxxx`、`87xxxx`、`92xxxx` 或对应 `bj` 前缀；这只是格式校验，不代表该代码当前已在北交所上市。旧代码也可能属于新三板或已发生变更，核对新旧代码对应关系及生效日期，不靠替换前缀推断新代码，不静默拼接两段行情。

日线复用 AKShare `stock_zh_a_hist(symbol=已核验的六位代码, period='daily', start_date=起始日期, end_date=截止日期, adjust=所选复权, timeout=15)`，实际提供方为东方财富。保存原表、按本文件字段映射生成 OHLCVA CSV；记录 `market=bse`、`exchange=BSE`、完整代码和名称、数据单位、复权与已收盘截止时点。日线 `future.csv` 由核验后的北交所交易日生成，随后调用 `scripts/predict.py --csv ... --future-csv ...`，不向该通用脚本添加 `--market` 参数。

盘中入口、自动取数与 CSV 用法见 [intraday.md](intraday.md#北交所)。AKShare 的沪深京历史接口提供北交所接入路径，实际标的及分钟周期覆盖以当次响应和交叉核验为准；空响应、异常、代码变更或缺行应报告真实原因，修复后重试，不自动换市场、换源或伪造行情。

调度器复用 XSHG 的 09:30–11:30、13:00–15:00 会话；它不是北交所官方日历，也不包含个股停牌。推理前核对北交所的休市公告、临时安排和上市状态，在 `data-source.json` 中另记具体公告链接、核验日期及结果。日历与北交所公告冲突时停止使用该调度结果，修正时间序列后再预测。不要仅凭第三方库的 `BSE` 别名选日历，要确认其对应的交易所全称。

北交所与沪深涨跌幅限制不同，按目标证券和日期适用规则解释输出；交易限制核验独立于 OHLC 合法性检查。模型输出保持原值，不用人为裁剪掩盖超限。较短上市历史、停牌和成交稀疏应显式说明，不插值凑满模型上下文。

### 核验与溯源

在推理前完成以下检查，并将结论写入任务输出目录的 `data-source.json`：

- 标的全称、完整代码、市场、交易所/数据商、实际来源链接或接口、请求参数（去除凭证）、抓取时间、交易所时区、价格/成交量/成交额单位及复权口径。
- 历史行数、起止时间、周期、是否覆盖最近一根已收盘 K 线；未收盘当日/当分钟 bar 排除。根据交易日历区分正常休市和数据滞后。服务声明的行情延迟明确列出。
- 数值完整性和 OHLC 关系、重复/倒序时间、异常缺口；异常缺口需确认是否停牌/休市/接口分页遗漏。存在口径冲突或明显缺数据时解决问题后再推理。
- 尽可能用交易所公开数据或另一个独立来源复核最近几个**已收盘且口径一致**的价格点。比较同一时间、市场、币种、复权方式和单位，差异超出报价最小单位或说明的舍入误差时调查原因。两家网站若共用同一底层供应商，不计作独立核验。
- 只取到一个可信来源时如实记录“单源，未交叉核验”；记录实际完成的检查，不用“保证准确”等语言代替证据。对未复核来源及延迟作事实说明，不虚构第二个来源。
- 保存原始下载数据和规范化 CSV，记录文件 SHA256，以及转换规则/是否剔除未收盘 bar。获取失败保留错误原因和请求对象；停止假数据生成及自动静默换源。确需更换公开来源时先说明原因，重新核验身份、字段和口径并记录所用来源。

把上述元数据摘要和 `data-source.json` 的绝对路径传入脚本 `--data-note`，最终回答链接数据来源及该文件。来源核验发生在调用模型前：CSV 数值检查脚本本身不证明数据的市场真实性。

## 预测时点

`future.csv` 示例格式：

```csv
timestamps
2026-09-22 09:35:00
2026-09-22 09:40:00
```

以上只是格式示例，真实时间必须按所选市场核实。采用 `exchange_calendars` 或 `pandas_market_calendars` 已支持的交易所日历，核对该版本覆盖日期、交易时区、午间休市、临时假期、夜盘及 bar 标签是开盘还是收盘时间。股票日线用真实交易日；`pd.bdate_range` 仅排除周末，不是交易所日历。分钟级别还要处理 session break 和闭市边界。

脚本验证未来时间严格递增、在历史之后且数量精确匹配，但不自行判断交易所开市状态，因此日历核验由调用方完成。连续市场 `--continuous-freq` 会检查选中历史窗口的间隔一致，不对缺失 K 线补值。

历史留出验证直接使用留出区间真实时间戳，仅时间特征作为未来输入；该段 OHLCVA 只参与预测之后的评分。
