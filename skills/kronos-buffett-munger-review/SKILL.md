# Kronos 预测证据审查

本 Skill 判断的是“预测发生前是否有足够证据支持这条预测”，不是事后判断预测命中与否。遵循客观、多维跟踪、重过程轻结果：只用预测当时可见的材料，按五个维度评分，不用目标日后来发生的行情倒推当时的合理性。不复制企业或基金评分卡的景气、ROE、流动性等维度。

## 操作系统与路径

在完整分发包中首次调用时，先读 [包内环境准备](references/package-environment.md)。由Agent检查并按实际任务准备依赖；用户无需双击任何启动器，已有环境不重复安装。

在 macOS 或迁移到其他电脑时，先读 [平台说明](references/platforms.md)。按当前系统解析 Python、工作目录和模型路径；文档中的 Windows 命令仅为示例。

## 执行规则

1. 读取当前对话最近一次 `kronos-kline-predict` 的预测文件、`run.json`、`data-source.json`、预测时实际可见的历史窗口和运行参数。文件只读。
2. 核对标的、市场、周期、复权方式、单位、数据来源、预测起点、历史截止时间、交易日历和信息边界。确认没有混入预测时点之后的数据或消息。
3. 只在预测前的信息边界内检查方向、幅度、历史波动、基准、OHLC 关系、交易时间和采样结果。不要读取或对照目标区间的实际行情。
4. 按“证据支持度评分”五项打分，再应用硬门槛。每项都写本次实际证据和扣分理由，不能用固定分数或上次结果。
5. 直接在当前对话输出三部分。一般审查不重新预测、训练或采样；只有用户明确要求新预测时才调用 `kronos-kline-predict`。

## 100 分制评分

### 1. 数据完整性与口径一致性：30 分

检查标的、周期、复权方式、价格/成交量/成交额单位、数据来源、预测起点、历史截止时间、交易日历、历史数据完整性，以及是否混入预测时点之后的信息。数据源只完成单源核验、时间边界不清或字段缺失时按实际缺口扣分。

### 2. 历史方向、幅度和基准比较：20 分

只使用模型实际可见的历史窗口，比较同周期收益、波动范围、历史分位数和简单基准（例如保持历史截止时最后收盘价不变）。历史趋势只能支持合理性，不能证明未来一定重复。没有足够历史依据时不给满分。

### 3. OHLC 与交易时间结构：20 分

检查：

```text
low <= open <= high
low <= close <= high
```

同时检查交易日是否正确、休市跳空是否合理、多根 K 线是否存在明显时间矛盾。该项是结构硬检查，错误不能被其他项目的高分抵消。日线 OHLC 不提供日内高低先后顺序，不能把它解释成确定的盘中路径。

### 4. 多次采样稳定性：20 分

检查不同采样之间的方向一致性、价格离散程度、区间宽度和反转频率。不能只看均值，也不能把多次采样均值当成上涨概率。只有一条路径时，按硬门槛限制该项得分。

### 5. 表述校准：10 分

检查是否使用区间和不确定性描述，是否把点预测误写成确定结果或概率，是否给出超出证据精度的目标价。精确价格而没有区间、波动范围或不确定性说明时，按硬门槛限制该项得分。

## 硬门槛

- 数据完整性、口径一致性或时间边界无法确认：第一项最多 `10/30`，总证据支持度最多 `40/100`。
- OHLC 基本关系错误：第三项记 `0/20`，明确写“存在结构错误”，总证据支持度最多 `35/100`。
- `sample_count = 1`：第四项最多 `5/20`。
- 给出精确价格但没有区间、波动范围或不确定性说明：第五项最多 `2/10`。

多个硬门槛同时触发时，先逐项限分，再取所有总分上限中的最低值。硬门槛只限制证据支持度，不替代具体理由。

## 巴菲特式意见

重点判断数据是否可靠、历史方向和幅度是否有依据、简单基准是否让预测显得多余，以及预测表述是否超出证据。输出事实、支持点、缺口和判断，不展开企业估值或基本面分析。

## 芒格式意见

重点检查 OHLC 和交易时间硬错误、趋势外推、无依据反转、跨休市跳空、采样不稳定、精确价格幻觉和可能失败路径。没有多次采样或训练证据时，说明“缺少证据”，不直接断言过拟合或数据泄漏。

## 固定交付格式

只输出以下三部分：

1. **巴菲特式意见**：判断预测依据是否足够，重点说明数据、历史方向和幅度证据。
2. **芒格式意见**：检查 OHLC、交易时间、采样稳定性和可能失败路径。
3. **综合判断**：必须包含：
   - 结论：`有一定合理性 / 依据薄弱 / 存在明确错误 / 材料不足`
   - `证据支持度：X/100`
   - 五项评分明细
   - 硬门槛是否触发
   - 最值得相信的部分
   - 最值得怀疑的部分
   - 明确写明“未经过目标行情事实验证”

不计算 MAE、RMSE、方向命中率或事后基准表现，不读取目标区间实际行情，不生成 JSON、图片、报告或附件，不把证据支持度写成预测概率。用户明确要求事后验证时，才另行执行实际行情对比、误差计算和简单基准比较。
