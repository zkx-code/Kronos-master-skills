## 📈 プロジェクト概要

Kronos Skills は、**清華大学のチームが開発した金融ローソク足モデルを中心に構成された、AI 支援型クオンツ分析ツール**です。

**ローソク足の予測値を生成するのは Kronos-small です。Skills は処理の流れを定め、実行を支えます。AI が依頼を理解し、Skills に沿ってツールを操作し、エラーに対処したうえで、結果を整理して説明します。**

**自然言語で依頼すると、AI は該当する手順に従って相場データを取得・検証し、モデルによる予測、バックテスト、ファインチューニング、可視化、予測の根拠評価を行います。モデルの能力を、実際に使える研究手順として提供します。**

**[shiyu-coder/Kronos](https://github.com/shiyu-coder/Kronos)：清華大学のチームが開発した金融ローソク足予測モデル。**

| 事前学習済みモデル | パラメータ数 | コンテキスト長 |
| :--- | ---: | ---: |
| Kronos-mini | 4.1M | 2,048 |
| **Kronos-small** | **24.7M** | **512** |
| Kronos-base | 102.3M | 512 |

同じ銘柄でも、最新の相場、入力期間、サンプリング設定が変われば、予測結果も変わることがあります。そのため、この Skills の価値は、継続的な過去データの検証と実際の相場の追跡によって評価する必要があります。確率的な観点から、**金融ローソク足の分析を効率化し、検証を通じて銘柄選びや判断の成功率を改善できるなら、その役割を果たしたと言えます**。

***現在のパッケージには、ハードウェア要件を抑えて利用しやすくするため、Kronos-small のローカル事前学習済み重みと対応する Tokenizer のみを同梱しています。*** Kronos-small は約2,470万パラメータ、512本のローソク足のコンテキスト長を持ち、モデル規模と計算資源のバランスを取っています。

## 🧩 5つのスキル

実際の相場データを出発点に、単独でも組み合わせても使える5つの Skills で、ローソク足予測、バックテスト、ファインチューニング、可視化、根拠評価を含む研究手順を実行します。

| スキル | 機能 | 利用する場面 |
| :--- | :--- | :--- |
| **`kronos-kline-predict`** | **過去の相場から将来の日足・分足を予測** | **将来のローソク足の傾向や騰落を調べる** |
| **`kronos-backtest`** | 元プロジェクトの実行入口で過去の成績を検証し、戦略とベンチマークを比較 | **モデルや戦略の過去の成績を評価する** |
| **`kronos-training`** | 自分の相場データで Tokenizer と Predictor をファインチューニング | **特定の銘柄にモデルを適応させる** |
| **`kronos-webui`** | 中国語・英語の Web 画面でデータを読み込み、設定を調整し、予測と実測値を比較 | **画面でモデルを操作し、予測と実際の相場の差を確認する** |
| **`kronos-buffett-munger-review`** | バフェットとマンガーの考え方を参考に、予測に十分な根拠があるかを評価。予測精度を表すものではない | **生成済みの予測を支える根拠を確認する** |

### **🎯 ローソク足予測：過去の相場から将来の足を予測**

**`kronos-kline-predict` は日足と1・5・15・30・60・120分足に対応します。予測時、AI は Skills の手順に従ってデータを取得・検証します。**

| **市場** | **取得方法** | **データ提供元** | **確認事項** |
| :--- | :--- | :--- | :--- |
| **上海・深圳 A 株** | **AKShare** | **新浪財経、東方財富など** | **必要な時間足、履歴の範囲、データの完全性** |
| **北京証券取引所** | **北交所市場アダプター** | **北交所公式銘柄一覧、東方財富など** | **各銘柄のコードとデータ提供範囲** |
| **米国株** | **yfinance** | **Yahoo Finance、東方財富など** | **取引所のタイムゾーン、通常取引時間、履歴範囲** |
| **香港株** | **yfinance** | **Yahoo Finance、東方財富など** | **銘柄コード、昼休み、半日取引の日程** |

<a id="workflow"></a>

**処理の流れ**

```text
銘柄・市場・日付・時間足 → 相場データの取得または読み込み → データと取引時間の検証
→ モデル入力の準備 → Kronos 推論 → 予測結果の確認 → グラフ・表・レポート
```

### **🕰️ バックテスト・回帰テスト：過去の成績を検証**

**`kronos-backtest` は元プロジェクトの Qlib、CSV 戦略、回帰テストの実行入口を再利用します。実モデルのバックテスト、ランダムな過去データの例、プログラム出力の回帰テストは、それぞれ異なる作業です。ランダムな例をモデルの性能と見なしたり、回帰テストの合格を相場予測の精度と解釈したりしないでください。**

**元の CSV 戦略には、実測価格が欠ける場合に予測価格を代用するなどの制限があり、使用時に明示する必要があります。実モデルやポートフォリオ戦略を評価する場合は、Qlib の実行入口を優先し、データ、取引費用、ベンチマークの設定を確認します。**

**処理の流れ**

```text
過去データ・モデル・既存の予測 → バックテスト入口の選択 → 独立した作業コピーの作成
→ 依存関係と設定の確認 → 元プロジェクトの手順を実行 → 指標・ベンチマーク・ログの確認
```

### **🧠 モデル学習：自分のデータでファインチューニング**

**`kronos-training` は、Qlib データの準備、Tokenizer／Predictor の個別ファインチューニング、CSV の順次学習、元プロジェクトの複数 GPU 用実行入口に対応します。元のソーススナップショットと既存の重みを保持し、新しい実験ディレクトリに学習結果を書き込みます。学習後は再度予測と過去データの検証を行います。学習損失の低下が、そのまま取引成績の改善を意味するわけではありません。**

**処理の流れ**

```text
学習データと事前学習済み重み → 時系列順に学習／検証／テスト集合を分割
→ 実験用コピーを作成して設定を確認 → Tokenizer／Predictor をファインチューニング
→ チェックポイントを保存 → 予測を再検証
```

### **🖥️ Web 画面：モデルを操作して結果を比較**

**`kronos-webui` は中国語と英語の画面を提供し、ローカルの CSV／Feather を読み込んで、モデル、デバイス、サンプリング設定を選択できます。**

**起動時に言語を選びます。通常の予測や結果グラフの作成には、Web 画面の起動は不要です。**

**処理の流れ**

```text
中国語／英語を選択 → WebUI 用の作業コピーを作成 → ローカルデータを読み込み → サービスを確認・起動
→ モデルとデバイスを選択 → 期間と設定を調整 → 予測・グラフ確認・結果保存
```

### **⚖️ 根拠評価：予測を支える十分な根拠があるかを確認**

**`kronos-buffett-munger-review` はウォーレン・バフェットとチャーリー・マンガーの思考法を参考に、呼び出し可能な予測評価スキルとして整理したものです。評価するのは予測の根拠の強さであり、予測精度ではありません。**

**バフェット式の根拠評価とマンガー式の逆向きの思考を、データの信頼性、過去の根拠、構造上の誤り、サンプリングの安定性、断定しすぎた表現の点検に落とし込みます。ここでの「蒸留」は思考法を手順に整理する意味です。両氏を対象にモデルを学習することではなく、本人や所属組織の意見を示すものでもありません。**

**処理の流れ**

```text
既存の予測と当時利用可能だった資料 → データ基準と情報の範囲を確認
→ バフェット式の根拠評価＋マンガー式の逆向きの点検 → 5項目の採点と上限制約 → 会話内で評価を提示
```

| **評価項目** | **満点** |
| :--- | ---: |
| **データの完全性と基準の一貫性** | **30** |
| **過去の方向・変動幅・ベンチマーク比較** | **20** |
| **OHLC と取引時間の構造** | **20** |
| **複数回サンプリングの安定性** | **20** |
| **表現の確度の適切さ** | **10** |

**合計は100点満点の根拠支持度であり、予測精度ではありません。モデルが予測を生成した後、対象期間の相場が実際に発生する前に使用します。データの境界が曖昧、OHLC の構造に誤りがある、サンプリングが1回だけ、といった場合は得点の上限制約が適用されます。会話内で評価を返し、添付ファイルは作成せず、対象期間に後から発生した相場も読み込みません。**

### ▶️ 使い方

#### **1. AI に依存環境を指定ディレクトリへインストールしてもらう**

**入力例：**

```text
kronos-kline-predict を使用して、ウォルマート WMT の次の取引日の5分足の動きを予測してください。
米国市場拡張版を使用し、米東部時間を明記して、グラフ、全ローソク足の表、中国語のレポートを出力してください。

スキルパッケージを D:\Kronos-Skills-Windows に展開しました。（実際のディレクトリに置き換えてください。）

このフォルダーをワークスペースにし、同梱の説明に従って環境を準備してください。
プロジェクトで使う Python ランタイム、仮想環境、モデル重み、ダウンロードキャッシュはこのフォルダー内に配置し、
予測結果は outputs フォルダーに保存してください。

最初に既存の環境、依存関係、モデルを確認し、互換性のあるものを再利用して、不足分だけを追加してください。
準備後に同梱のチェックを実行し、モデルとデバイスが利用可能なことを確認してから、上記の予測を実行してください。

最後に、環境、予測グラフ、全ローソク足の表、中国語レポートの保存場所を教えてください。
```

この依頼を Agent に送ると、推論前に環境を準備し、PyTorch、NumPy、pandas、einops、huggingface_hub、safetensors、Matplotlib、tqdm などの不足する依存関係を、同梱の一覧に従ってインストールします。

#### **2. コマンドラインでインストールする**

詳しくは [Windows コマンドラインインストール手順（中国語）](./Windows命令行安装步骤.md)を参照してください。
